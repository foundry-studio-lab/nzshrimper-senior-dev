# senior-dev v0.4 friction pass — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Break the test loop (scoped reruns, one full run, proven pre-existing failures, contradiction stop, a ship override that never ships a diff-caused failure) and turn four other bypass patterns into first-class operations.

**Architecture:** Test execution and proof live in a new `scripts/lib/test-runner.mjs` (CLI-only). Gate *evaluation* stays in `scripts/lib/state.mjs`, because the guard bundle copies only that file (`state-cli.mjs:546-547`). The CLI gains `test`, `ship`, `reclassify`, `finish --no-change`, `skills-config set-tests`.

**Tech Stack:** Node ESM, no dependencies, `node:test`. Run tests with `node --test tests/*.test.mjs` (bare `tests/` fails on this Node).

**Spec:** `docs/superpowers/specs/2026-09-30-v0.4-friction-pass-design.md`

## Global Constraints

- No new dependencies; Node built-ins only.
- `state.mjs` must stay self-contained (no imports from other plugin files): the guard bundle ships it alone as `state-lib.mjs`.
- A repo with no `tests` config, or `tests: {"none": true}`, behaves exactly as 0.3.1 (all 177 existing tests stay green unchanged).
- Pre-0.4 state files (no `baseHead`, `testRuns`, etc.) must still read and gate.
- skills.json version: `tests` present → 4; else `models` present → 3; else 2. `readSkillsConfig` accepts 1–4.
- Every new CLI error goes through `fail()` (exit 1, `senior-dev: ` prefix).
- Tests use mkdtemp git repos and fake test commands (`node -e` scripts that exit 0/1 and write JUnit XML); never the real repo.
- In this repo, write files with Read/Edit/Write, not Bash heredocs or sed: the TSP editorial hook blocks shell writes unpredictably.
- Version is 0.4.0 in `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.

## Review Focus

1. **Stale JUnit report** — a report file left from an earlier run must never be parsed as this run's result: delete it before each run; a run that writes none records `failures: null`.
2. **Runner crash on the base worktree** — no `node_modules`, a syntax error, or the test not existing on base must give `proven: false`, never `true`; only an id present AND failed in both reports proves.
3. **Worktree vs main checkout** — state is at the main root, but tests, the would-commit tree, and `HEAD^{tree}` must come from the checkout the CLI or hook runs in (`git rev-parse --show-toplevel` of cwd).
4. **Shell quoting in templates** — file names with spaces or `'` substituted into `{files}` / `{test}` must reach the command intact and must not execute.
5. **Deleted and renamed files in `--affected`** — deleted paths must not be passed to `related` (`--diff-filter=d`); untracked non-ignored files must be included.

Each of these has a pinned test in its owning task (marked **RF1–RF5**).

### Task 2: Test runner — run, record, contradiction

**Files:**
- Create: `scripts/lib/test-runner.mjs`
- Modify: `scripts/state-cli.mjs` (new `test` case dispatching to the runner)
- Test: `tests/test-runner.test.mjs`

**Interfaces:**
- Consumes: `cfg.tests` (Task 1), `state.baseHead` (Task 1).
- Produces (exported from `test-runner.mjs`):
  - `shq(s: string) -> string` single-quote shell escape.
  - `fill(template: string, {files?: string[], test?: string}) -> string` — `{files}` → space-joined `shq` values; `{test}` → `shq(id)`; `{file}`/`{name}` → `shq` of the id halves split at the first ` > ` (no ` > ` → `{file}` = id, `{name}` = `''`).
  - `parseJUnit(xmlText: string) -> {passed: string[], failed: string[]}`; ids `classname > name`; a testcase containing `<failure` or `<error` is failed, `<skipped` is neither; XML entities `&amp; &lt; &gt; &quot; &apos;` decoded.
  - `wouldCommitTree(cwd) -> string` — temp index: copy `.git index` path from `git rev-parse --git-path index` to a tmp file, `GIT_INDEX_FILE=<tmp> git add -A`, `git write-tree`, delete tmp. The real index is never written.
  - `headTree(cwd) -> string|null` — `git rev-parse HEAD^{tree}`, null with no commits. Define and export it in `scripts/lib/state.mjs` in THIS task (the guard bundle needs it there, Task 4); `test-runner.mjs` imports it.
  - `runTest({repoRoot, cwd, state, cfg, kind, files?, test?}) -> {run, exit}` — appends `run` to `state.testRuns` (caller writes state).
- State written: `state.testRuns[]` per spec §3.2 (`id` = 1 + max existing id; `sinceFull` = id of the latest `full` run or null; `failures` = parsed `failed` or `null`); `state.testHistory[id] = [{phase, ok, run}]`; `state.contradictions[] {test, phase, at, resolved?: {reason, at}}`; zero exit stamps `phases[cur].testsGreenAt`.
- CLI: `test --affected [files…]` | `--one <id>` | `--full` | `--build` | `--resolve <id> --reason "<text>"`. Positional args after `--affected` are the files. The CLI exits with the command's exit code. No `tests` config (or `none`) → `fail('no tests config - run skills-config set-tests, or use tests-green')`.

- [ ] **Step 1: Write failing tests** (helper writes a fake runner: `node -e` script taking args, writing JUnit to `.senior-dev/junit.xml` from a fixture file, exiting per a flag file):
  - `shq round-trips hostile names` (**RF4**): `execFileSync('sh', ['-c', 'printf %s ' + shq("a b'$(touch x)")])` prints the literal and no file `x` is created.
  - `fill substitutes files, test, file and name`.
  - `parseJUnit` on a fixture with 1 pass, 1 failure, 1 error, 1 skipped, and `&amp;` in a name → exact arrays.
  - `wouldCommitTree matches HEAD tree after committing` and leaves `git diff --cached` empty (real index untouched); includes an untracked file; excludes an ignored file.
  - `--full records failures from the report`, run exits 1, `testsGreenAt` not set.
  - `stale report is not parsed` (**RF1**): pre-write a report with a failure, run a command that writes no report and exits 0 → `failures: null`, green.
  - `--affected defaults to files changed since the last full run` (**RF5**): commit, full run, then modify `a.js`, delete `b.js`, add untracked `c.js` → recorded `files` equals `['a.js','c.js']` (sorted); `related` template received them.
  - `--affected with no changes records green with files []` and runs nothing (marker file absent).
  - `--affected without related falls back to full`.
  - `contradiction: fail, pass, fail on one id prints CONTRADICTION and records it`; a second id with pass, fail does not.
  - `--resolve clears the stop` (records `resolved`); unknown id → exit 1.
  - `runs from a worktree use the worktree checkout` (**RF3**): state in main root, run invoked with cwd = a `git worktree add` dir → `run.head` is the worktree's HEAD and the command ran there.
  - `no tests config refuses with the message above`.
- [ ] **Step 2:** run the file → FAIL.
- [ ] **Step 3: Implement.** Command runs via `spawnSync('sh', ['-c', cmd], {cwd, stdio: 'inherit', env})`. Delete the report file (resolved against `cwd`) before spawning. Affected default files: `git diff --name-only --diff-filter=d <base>` plus `git ls-files --others --exclude-standard`, run in `cwd`, where `<base>` = latest full run's `head`, else `state.baseHead`, else `HEAD`; sorted, de-duplicated. `tree` = `wouldCommitTree(cwd)`.
- [ ] **Step 4:** run the file + whole suite → PASS.
- [ ] **Step 5: Commit** `feat: state-cli test - scoped runs, JUnit failures, contradiction stop`.
