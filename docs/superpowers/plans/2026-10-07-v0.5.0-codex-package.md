# senior-dev v0.5.0 (Codex / ChatGPT app package) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship senior-dev as a native Codex plugin that the ChatGPT app installs from a local marketplace folder.

**Architecture:** A `.codex-plugin/plugin.json` manifest lives in the repo beside `.claude-plugin/`. A zero-dependency build script copies the runtime files into `dist/codex-marketplace/plugins/senior-dev/`, turns each `commands/*.md` into a skill, rewrites `${CLAUDE_PLUGIN_ROOT}` in skill text, and writes `.agents/plugins/marketplace.json`. Claude Code packaging is unchanged except for the version.

**Tech Stack:** Node ESM (`.mjs`), `node:fs`/`node:path` only, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-07-v0.5.0-codex-package-design.md`

## Global Constraints

- Zero dependencies; node built-ins only.
- Manifest field values are exactly as in spec §3 (copy them verbatim); `defaultPrompt` ≤ 3 strings, each < 128 characters.
- Marketplace file content is exactly spec §4's JSON.
- Package copies only: `.codex-plugin/`, `skills/`, `scripts/`, `hooks/`, `LICENSE`, `README.md`, `PRIVACY.md`, `CHANGELOG.md` — never `tests/`, `docs/`, `.senior-dev/`, `.claude/`, `.git/`, `dist/`, `.DS_Store`.
- Version `0.5.0` in `.claude-plugin/plugin.json`, both version fields of `.claude-plugin/marketplace.json`, and `.codex-plugin/plugin.json`.
- `hooks/hooks.json` is copied unchanged (keeps `${CLAUDE_PLUGIN_ROOT}`).
- Session hygiene: Write/Edit for files; one plain git command per Bash call; tests via `state-cli test --full`/`--one` (this repo now has a tests config) before commits; full suite command is `node --test tests/*.test.mjs`.

## Review Focus

1. **`--out` pointing at the repo root, a parent of it, or a source folder** — the build deletes its output dir first; it must refuse any out dir that equals or contains the repo root, or lies inside `skills/`, `scripts/`, `hooks/`, `commands/` or `.codex-plugin/`. Test in Task 2.
2. **Run from another working directory** (e.g. the main checkout or `/tmp`) — paths resolve from the script's own location, not cwd. Test in Task 2.
3. **A command file without a `description` in its frontmatter** — the build fails naming the file, never writes an empty description. Test in Task 2.
4. **A description containing `:` or quotes** — the generated SKILL.md frontmatter stays valid (description emitted as a JSON-quoted string). Test in Task 2.
5. **Stray `.DS_Store` in a copied folder** — not copied. Test in Task 2.
