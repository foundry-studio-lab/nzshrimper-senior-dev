# senior-dev v0.5.0 — a native Codex / ChatGPT app package

Date: 2026-10-07. Status: design agreed with the operator in session
(sections 1 and 2 approved), awaiting written-spec review.

## 1. Why

The operator wants to install senior-dev in the ChatGPT app. senior-dev ships
only the Claude Code format (`.claude-plugin/`). The Codex CLI happens to read
that format, but the ChatGPT app installs plugins from a local marketplace
folder in the Codex format, the way the Talking Shrimpers editorial plugin is
installed (`dist/codex-marketplace`).

The format is taken from Codex's own `plugin-creator` skill
(`references/plugin-json-spec.md`): a `.codex-plugin/plugin.json` manifest
with an `interface` block for the app's card, and an
`.agents/plugins/marketplace.json` listing the plugin with `policy` and
`category`.

## 2. Goals and non-goals

Goals: a `.codex-plugin/plugin.json` in the repo; a build that writes an
installable local marketplace folder; the seven slash commands available as
skills in that package; proof that the package installs; the Codex CLI moved
onto the new package.

Non-goals (parked, operator's decision 2026-10-05): making the commit and stop
gates fire in Codex. A 2026-09-25 Codex session log shows the SessionStart
hook does fire, but Codex runs shell commands through a tool named `exec`
whose input is JavaScript, so the `PreToolUse` matcher `Bash` and the
`tool_input.command` read never match there. Packaging neither fixes nor
worsens this; the git-hook guard still blocks commits and pushes in any app.
No logo or screenshots in this release.

Compatibility: the Claude Code plugin is unchanged (its manifest only gains
the new version number).

## 3. The Codex manifest: `.codex-plugin/plugin.json`

At the repo root, beside `.claude-plugin/`.

| Field | Value |
|---|---|
| `name` | `senior-dev` |
| `version` | `0.5.0` |
| `description` | the Claude manifest's description, with "in Claude Code" removed |
| `author` | `{ "name": "Foundry Studio", "email": "nzshrimper@gmail.com", "url": "https://foundrystudio.app" }` |
| `homepage`, `repository` | `https://github.com/foundry-studio-lab/nzshrimper-senior-dev` |
| `license` | `MIT` |
| `keywords` | `["code-review", "workflow", "tdd", "git", "developer-tools"]` |
| `skills` | `./skills/` |
| `hooks` | `./hooks/hooks.json` |
| `interface.displayName` | `senior-dev` |
| `interface.shortDescription` | `A disciplined senior developer for every coding session` |
| `interface.longDescription` | one paragraph: classification, skill chain, review gates, docs gate, clean finish; notes that the git-hook guard enforces commits and pushes |
| `interface.developerName` | `Foundry Studio` |
| `interface.category` | `Developer Tools` |
| `interface.capabilities` | `["Interactive", "Write"]` |
| `interface.websiteURL` | `https://foundrystudio.app` |
| `interface.privacyPolicyURL` | `https://github.com/foundry-studio-lab/nzshrimper-senior-dev/blob/main/PRIVACY.md` |
| `interface.defaultPrompt` | `Start a senior-dev session for this task`, `Show the senior-dev session status`, `Finish and close this senior-dev session` |

`defaultPrompt` holds at most 3 strings, each under 128 characters (the app
ignores or truncates beyond that).

## 4. The build: `scripts/build-codex-package.mjs`

`node scripts/build-codex-package.mjs [--out <dir>]` (default
`dist/codex-marketplace`, git-ignored). Zero dependencies. It deletes the
output directory first, then writes:

- `.agents/plugins/marketplace.json`:
  `{ "name": "nzshrimper-senior-dev", "interface": { "displayName": "Foundry Studio" }, "plugins": [ { "name": "senior-dev", "source": { "source": "local", "path": "./plugins/senior-dev" }, "policy": { "installation": "AVAILABLE", "authentication": "ON_INSTALL" }, "category": "Developer Tools" } ] }`
- `plugins/senior-dev/`, a copy of: `.codex-plugin/`, `skills/`, `scripts/`
  (with `scripts/lib/`), `hooks/`, `LICENSE`, `README.md`, `PRIVACY.md`,
  `CHANGELOG.md`. Nothing else: no `tests/`, `docs/`, `.senior-dev/`,
  `.claude/`, `.git/`, `dist/`.
- One skill per command: each `commands/<name>.md` becomes
  `plugins/senior-dev/skills/<name>/SKILL.md`, with frontmatter
  `name: <name>` and `description:` taken from the command's own
  `description` frontmatter (prefixed `senior-dev: `, ≤1024 characters), and
  the command body unchanged below it. A command whose body uses
  `$ARGUMENTS` keeps it; the skill text says the arguments come from the
  user's message.
- In every copied skill text (the command skills and
  `skills/conductor/SKILL.md`), `${CLAUDE_PLUGIN_ROOT}` (which Claude Code
  substitutes and Codex may not) becomes `<plugin>`, and each such skill gets
  one line: "`<plugin>` is this plugin's folder; the senior-dev session-start
  banner prints the state CLI's exact path." `hooks/hooks.json` keeps
  `${CLAUDE_PLUGIN_ROOT}`: the 2026-09-25 Codex log shows the SessionStart
  hook resolving it.

Added after review (2026-10-08):

- Claude Code's `` !`cmd` `` lines (run by Claude Code before the prompt,
  never by Codex) become "Run this command and use its output: `cmd`".
- Output safety, because the build deletes its output first: both paths are
  compared as real paths (symlinks resolved, true case); an out that
  contains the repository is refused; inside the repository only
  `dist/<folder>` may be written; a non-empty out is emptied only when it is
  a previous build of this package: nothing but `.agents/plugins/marketplace.json`
  (named `nzshrimper-senior-dev`) and `plugins/senior-dev/`.
- `scripts/state-cli.mjs` reads the version from `.codex-plugin/plugin.json`
  when `.claude-plugin/plugin.json` is absent (the package has no Claude
  manifest), so the packaged guard can report itself stale.

It prints the output path and the
`codex://plugins/senior-dev?marketplacePath=<absolute marketplace.json path>`
deeplink.

## 5. Version

0.5.0 in `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`
(both version fields) and `.codex-plugin/plugin.json`. A test fails if the
three disagree.

## 6. Proof it installs

- **Unit tests** (`tests/codex-package.test.mjs`, in the normal suite, no
  network): build into a temp dir, then assert: the manifest's required
  fields and the `interface` limits; the marketplace entry's exact shape;
  seven command skills plus `conductor`, each with valid frontmatter; no
  dev-only path copied; a second build into the same dir leaves no stale file;
  the three versions agree.
- **Isolated install smoke** (`tests/SMOKE.md` item 30, run live): a fresh
  temporary `CODEX_HOME`; `codex plugin marketplace add <dist>`;
  `codex plugin add senior-dev@nzshrimper-senior-dev`; `codex plugin list`
  shows `installed, enabled  0.5.0`; the installed cache has the eight skills;
  the temp home is removed and the real `~/.codex` is byte-identical.
- **Real install:** remove the Codex CLI's git-based `nzshrimper-senior-dev`
  marketplace and its `senior-dev` install, then add the built folder and
  install from it (one senior-dev, not two). The operator adds the same
  folder in the ChatGPT app and confirms the card shows and a skill runs
  (SMOKE item 31, operator-run).

## 8. Ceilings

- In Codex and the ChatGPT app, the commit and stop gates do not fire (see §2);
  the SessionStart reminder and the git-hook guard do.
- The package is a copy: after any change, rebuild and reinstall.
- No logo or screenshots; the app shows its default card art.
