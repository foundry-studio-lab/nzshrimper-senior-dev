# senior-dev v0.4.2 — hardening pass and one review runner

Date: 2026-10-01. Status: approved 2026-10-01; amended 2026-10-02 after
review (runner lifecycle, write check); shipped in 0.4.2.

## 1. Why

Two groups the operator chose from the post-0.4.1 list.

**Hardening (logged during the 0.4.0/0.4.1 builds):**

| Gap | Evidence |
|---|---|
| An unquoted `$(…)` containing spaces after `-C` (e.g. `git -C $(git rev-parse --show-toplevel) push`) escapes the Claude Code gate's classifier entirely | 0.4.0 final review; parked for 0.4.x |
| The stop gate and the session-start banner list open items without the test rules (`finish` and `status` include them) | 0.4.0 fix-wave re-review; parked |
| `skills-config set-tests` can rewrite or switch off the tests config mid-session, unlogged | 0.4.0 finish pass M7 |
| `--affected` diffs against the full run's commit, so files edited-but-uncommitted at full-run time are re-run | SMOKE 25 (0.4.1) |

**From the 441-session audit, still unbuilt:**

| Gap | Evidence |
|---|---|
| In the Codex app the Claude review pass cannot run (no Claude subagents there) | 14 degraded reviews |
| No rule for a Codex review pass that hangs or returns garbage | 7 degrades, each handled differently |

A probe on 2026-10-01 confirmed the Claude lane is feasible: `claude -p
--model sonnet --permission-mode plan --allowedTools "Read,Grep,Glob,
Bash(git diff:*),Bash(git show:*),Bash(git log:*)"` returned the exact JSON
verdict contract, found a planted bug, and wrote nothing. The same probe
found macOS has no `timeout` command, so timeouts must be enforced in Node.

## 2. Goals and non-goals

Goals: close the four hardening gaps; give every host the same read-only,
timeout-bounded, write-checked way to run a review with either vendor.

Non-goals: recording verdicts automatically (the conductor still runs
`state-cli review`); changing review tiers or the cycle cap; a review lane
for hosts other than Claude Code and the Codex app.

Compatibility: repos without a tests config, and sessions started before
0.4.2, behave as in 0.4.1 except where §3 deliberately blocks more.

## 3. Hardening

### 3.1 Unquoted command substitutions in the classifier

`scripts/commit-gate.mjs` already swaps each quoted span for one
placeholder token before splitting a command into words. It now also
swaps, outside quotes, each `$(…)` span (balanced, nested parentheses
included) and each backtick span for one placeholder token holding the
span's text. A `-C` (or `-c`, `--repo`, any value flag) whose value is
such a token takes it as its value, so the subcommand after it is found
and classified. `literalToken` already maps any value containing `$` or a
backtick to unresolved, so the `-C` target is `UNRESOLVED` and coverage
fails closed (§3.3 of the 0.4 spec). The text inside each substitution
is also classified as a command of its own, because it runs: `echo $(git
push)` is a push. Unbalanced `$(` with no closing parenthesis: the rest
of the segment becomes one token and its text is classified too (fail
closed).

Delivered scope (amended during review): the same treatment covers process
substitution `<(…)` / `>(…)`, substitutions inside double quotes (handled
when the substitution contains no nested double quotes; see §8), and tokens
split by parentheses, because bash runs them and leaving any of them
unclassified is a fail-open path past the gate.

Tests: `git -C $(git rev-parse --show-toplevel) push` and `git -C $(pwd)
push origin main` classify as `push` with an unresolved target;
`gh --repo $(echo o/r) pr create` as `pr-create`; `git commit -m $(cat
msg) && git push` classifies both segments; `echo $(git push)` and
`` echo `git push` `` classify as `push` (inner text classified);
`git commit -m "$(cat msg)"` stays a commit only; every existing
classifier test unchanged.

### 3.2 Test items in the stop gate and the session-start banner

`openItems(repoRoot, state)` moves from `scripts/state-cli.mjs` into
`scripts/lib/state.mjs` (still import-free of plugin files; it already
uses only `readSkillsConfig`, `headTree`, `testBlockers` and git). The CLI
(`status`, `finish`), `scripts/stop-gate.mjs` and `scripts/session-start.mjs`
all call it. No-config repos: identical output to today. The stop gate's
snapshot hash then includes test items, so a session whose only open items
are test items is challenged once like any other.

Tests: with a tests config and no full run, the stop gate's challenge and
the session-start banner both list `tests: no full test run recorded …`;
without a config, both are unchanged.

### 3.3 `set-tests` locked mid-session

`skills-config set-tests` checks the active session: when one exists and
it has any `testRuns`, the command is refused with `set-tests refused - this
session already has test runs; changing the commands now would change what
those runs mean. Rerun with --by-operator (the operator's yes) to change
them anyway.` With `--by-operator` (no value) it proceeds and appends
`state.testsConfigChanges[] {from, to, at}` (`from`/`to` the whole tests
blocks); `status` prints `tests config changed mid-session (N)` when any
exist. No active session, or an active session with no runs: unchanged.

Tests: refused with runs, allowed and logged with `--by-operator`, allowed
silently with no runs and with no session; `--by-operator` takes no value.

### 3.4 `--affected` diffs against the tested state

In `runTest`, when the latest full run F exists, the diff base for
`--affected` becomes F.tree when that tree object exists
(`git cat-file -e`), else F.head, else (both unusable) the run escalates
to `full` as today. The diff is tree-to-tree: the base against the
current would-commit tree (`git diff <base> <tree>`, the tree built from a
throwaway index with `git add -A`, so untracked files are included on both
sides). That lists exactly the files changed since the state F tested
(modified, added, deleted), so an edit that was uncommitted at full-run
time is no longer re-run, and the headless-F case from 0.4.1 becomes the
general case. Tree-to-tree also means an untracked file present at F and
still on disk does not read as deleted (a working-tree diff against F.tree
reported it as deleted, since it is not in the index); one deleted since F
does. With no full run the base is unchanged (`baseHead`, else HEAD, else
the empty tree), diffed the same way.

Tests: a file edited before an uncommitted full run, then committed, is
not in the next `--affected` list; a file edited after the full run is; a
deletion since F still escalates to full; a pruned F.tree falls back to
F.head; the existing 0.4.1 headless-F tests still pass.

## 4. One review runner: `scripts/review-run.mjs`

```
node <plugin>/scripts/review-run.mjs --reviewer codex|claude --phase <p>
  --range <a..b> [--spec <path>|none] [--effort <low|medium|high|xhigh>]
  [--model <haiku|sonnet|opus|fable>] [--timeout <minutes>]
```

1. **Prompt.** Built from `skills/conductor/references/review-prompt.md`
   (the renamed `codex-review-prompt.md`; it now serves both vendors) with
   `<RANGE>`, `<PHASE>`, `<SPEC>` filled. Flags are required per reviewer:
   `--effort` for codex, `--model` for claude (the conductor reads both from
   `state-cli models`).
2. **Run, read-only.**
   - codex: `node <companion> task --fresh --effort <e> "<prompt>"`, the
     companion found as today (`~/.claude/plugins/cache/*/codex/*/scripts/
     codex-companion.mjs`, newest), override with `SENIOR_DEV_CODEX_COMPANION`.
   - claude: `claude -p --model <tier> --permission-mode plan
     --allowedTools "Read,Grep,Glob,Bash(git diff:*),Bash(git show:*),
     Bash(git log:*)" --output-format text "<prompt>"`; binary overridable
     with `SENIOR_DEV_CLAUDE_BIN`.
   Both run as an async child spawned detached in its own process group,
   in the checkout root, stdout/stderr captured (64 MB cap). The child's
   env carries `SENIOR_DEV_REVIEW_RUN=1`, on which the stop gate and the
   session-start banner stand down (the commit gate and guard never honour
   it).
3. **Write check.** Before and after each attempt, compare `git status
   --porcelain`, `git rev-parse HEAD`, a hash of `git diff HEAD --binary`,
   and the would-commit tree (untracked files included). The senior-dev
   state file is deliberately not compared: the conductor writes it during
   a review. Any difference: print `WRITE DETECTED: <reviewer> changed the
   repo during a read-only review` with the difference, exit 4, no retry.
   The check never fails open: inside a git repo, any error taking either
   snapshot exits 3 with `--reason "write check failed: <message>"` (before
   the reviewer is spawned, or before its verdict is read). Finding the
   root counts: only a `rev-parse --show-toplevel` failure whose stderr
   has a line starting `fatal: not a git repository (or any` (git's
   outside-a-repo form, including the mount-point variant) means no
   snapshot to compare; any other failure (no git, dubious ownership,
   corrupt `.git` such as `fatal: not a git repository: <gitdir>`) exits 3
   the same way.
4. **Verdict.** The last line of stdout that parses as a JSON object with
   `verdict` in {APPROVED, NEEDS_REVISION} and `concerns` an array is the
   verdict.
5. **Hang and garbage rule.** Each attempt has a Node-enforced timeout
   (on expiry the whole process group gets SIGTERM, then SIGKILL after
   the full 2 s grace even if the leader exits first; the runner waits for
   both the SIGKILL and the child's stdio to close before the after-
   snapshot): default by effort/tier
   — low/medium/haiku/sonnet 15 min, high/opus/fable 25 min, xhigh 40 min;
   `--timeout` overrides. SIGINT/SIGTERM/SIGHUP to the runner kill the
   reviewer's group and exit 130/143/129. On a timeout or a reply with no
   valid verdict:
   one retry, fresh (a new codex thread or a new `claude -p`). A second
   failure exits 3 and prints the exact line to record, e.g.
   `state-cli degrade --wanted "codex review (phase implement)" --used none
   --reason "timed out twice (25 min each)"`.
6. **Missing tool.** Companion not found or binary ENOENT: exit 3 with
   the degrade line naming the cause. Other spawn errors: "failed to start
   (<code>)". Not logged in: non-zero exit with an auth message on stderr,
   checked before any verdict. No retry. Unexpected runner errors also
   exit 3 with a degrade line.
7. **Success.** Print the verdict JSON on stdout, exit 0. The runner never
   writes senior-dev state.

## 5. Conductor changes

- §3 Codex pass and §5 finish pass: run the review through
  `review-run.mjs --reviewer codex`; the manual before/after git commands
  and the "re-ask once for JSON" step go (the runner does both).
- §3 Claude pass: in Claude Code, unchanged (a subagent). In a host with
  no Claude subagent tool (the Codex app): `review-run.mjs --reviewer
  claude --model <tier from state-cli models --phase review>`, recorded
  with `state-cli review ... --skill claude-headless`.
- Exit 3: record the printed degrade line and tell the operator. Exit 4:
  stop and tell the operator immediately.
- Engage step: the Codex-host check names `claude` CLI presence.

## 8. Ceilings

- The Claude headless lane needs the `claude` CLI installed and logged in
  on the machine running the Codex app.
- Plan mode plus the tool allowlist (Claude lane) and Codex's read-only
  default are the primary protection, not a strict guarantee: the
  allowlisted `git diff` / `git show` / `git log` accept write-capable
  options such as `--output=<path>`. The write check is the after-the-fact
  backstop for both vendors.
- `openItems` fails closed only when evaluating the rules of a valid tests
  config throws; a corrupt or unreadable `skills.json` reads as "no tests
  config" (`readSkillsConfig` returns null).
- A review that legitimately needs longer than the default timeout needs
  `--timeout`.
- Ignored paths (the `.senior-dev` state included) and loose git objects
  are outside the write check.
- A reviewer that deliberately daemonises a detached child which writes
  after the reviewer exits is outside the backstop (plan mode / the codex
  sandbox are the guarantee).
- An auth message printed only on stdout reads as "no JSON verdict".
- `skills.json` and the `testsConfigChanges` log are two separate writes
  (config first).
- `cd X && git push` and an explicit refspec without the guard remain the
  documented 0.4 ceiling; §3.1 only closes the unquoted-substitution shape.
- Nested double quotes inside a double-quoted substitution (e.g.
  `echo "$(git -c "x=y" push)"`) can hide a push from the Claude Code
  classifier: the flat quote regex cuts the span. Same ceiling class as
  `cd X && git push`; the guard's pre-push hook still checks pushed shas
  when installed.
